## 1. Ядро: фреймворк и язык

### Next.js 15 (App Router)
- **Что:** React-фреймворк. Даёт маршрутизацию, рендеринг на сервере (SSR), серверные функции, сборку.
- **Зачем здесь:** серверный рендер (важен для SEO), серверные эндпоинты, лёгкий деплой на Vercel.
- **Где:** вся папка `src/app/` (страницы, layout, API). Конфиг — `next.config.mjs`.

### React 19
- **Что:** библиотека для интерфейсов из компонентов.
- **Зачем:** весь UI — это React-компоненты.
- **Где:** `src/components/*`. Хуки: `useState`, `useEffect`, `useMemo`, `useRef`, `useCallback`, `useContext`.

### TypeScript
- **Что:** JavaScript с типами (ловит ошибки до запуска).
- **Зачем:** надёжность, автодополнение.
- **Где:** все `.ts/.tsx`. Типы данных — `src/lib/types.ts`. Конфиг — `tsconfig.json`.

## 2. Ключевые концепции Next.js (важно понять)

### Server Components vs Client Components
- По умолчанию компоненты — **серверные** (рендерятся на сервере, быстрее, видят секреты).
- Если компонент использует интерактив (`useState`, события, `localStorage`) — вверху файла пишем **`"use client"`** → он клиентский.
- **Где у нас:** данные тянет серверный `app/page.tsx` через `publicData.server.ts`,
  а рисуют их клиентские компоненты (корзина, фильтры, модалки) через Context.

### App Router (файловая маршрутизация)
- Папка = маршрут. `app/page.tsx` → `/`, `app/admin/page.tsx` → `/admin`.
- `layout.tsx` — обёртка вокруг страниц (общая для группы).
- **Где:** `src/app/` (главная, `about/oferta/privacy`, `admin/*`, `api/*`).

### Route Handlers (API)
- **Что:** серверные эндпоинты (бэкенд внутри Next).
- **Где:** `api/order` (заказ), `api/review` (отзыв), `api/upload` и `api/banners`
  (картинки), `api/admin/staff/password` (пароль сотруднику).

### Middleware
- **Что:** код, который выполняется до отрисовки страницы, на границе сети.
- **Зачем:** защита `/admin` — проверка сессии и роли **на сервере**, до того как
  что-либо отрендерится.
- **Где:** `src/middleware.ts` + `src/lib/supabase/middleware.ts`.

### Режимы рендеринга
- `force-dynamic` — страница рендерится на каждый запрос (сейчас так работает главная,
  чтобы правки в админке были видны сразу).
- ISR/кэш — планируется, когда каталог наполнится (см. роадмап в `STATUS.md`).

### Переменные окружения
- `NEXT_PUBLIC_*` — видны в браузере (публичные).
- Без префикса — **только сервер** (секреты: `SUPABASE_SERVICE_ROLE_KEY`, `TELEGRAM_BOT_TOKEN`).
- **Где:** `.env.local` (локально, в git не попадает), шаблон — `.env.example`,
  прод — Vercel → Settings → Environment Variables.

## 3. Стилизация

### CSS-переменные (custom properties) + глобальные классы
- **Что:** дизайн-токены (цвета, шрифты) и адаптивные значения в CSS-переменных.
- **Зачем:** один источник правды для темы + адаптив без переписывания компонентов.
- **Где:** `src/app/globals.css` (`:root { --accent, --py, --menu-cols ... }`),
  инлайн-стили компонентов ссылаются на них.

### next/font
- **Что:** подключение шрифтов Google (self-hosted, без внешних запросов, без «прыжков» текста).
- **Где:** `src/app/layout.tsx` — Cormorant Garamond (акценты), Jost (текст),
  Old Standard TT (заголовки, интерим вместо церковнославянского устава).

## 4. Состояние на клиенте

### React Context
- **Что:** способ делиться состоянием между компонентами без передачи через пропсы.
- **Где:** `CartContext` (корзина), `PublicDataProvider` (данные витрины из SSR),
  `AdminAuthContext` (текущий пользователь и роль в админке).

### localStorage
- **Что:** хранилище в браузере (переживает перезагрузку).
- **Где:** корзина (`ss_cart_v1`) в `src/features/cart/CartContext.tsx`.
- Данные админки в localStorage больше **не** живут — всё читается из Supabase
  (`src/features/admin/db.ts`).

## 5. Бэкенд и сервисы

### Supabase
- **Что:** «бэкенд из коробки» — Postgres + авторизация + хранилище файлов, с бесплатным тарифом.
- **Зачем:** одна платформа под БД, Auth и картинки — меньше сервисов и ключей.
- **Где:** клиенты `src/lib/supabase/{client,server,admin,middleware}.ts`;
  схема — `supabase/migrations/`; пакеты `@supabase/supabase-js`, `@supabase/ssr`.

### PostgreSQL (внутри Supabase)
- **Что:** реляционная БД (таблицы, связи).
- **Ключевые понятия у нас:**
  - **Таблицы и связи** (`products` → `categories`, `promos` → `products`, `order_items` → `orders`).
  - **RLS (Row Level Security)** — правила доступа к строкам прямо в БД: читать
    каталог публично, писать — staff, удалять — только admin.
  - **Функции и триггеры** — `handle_new_user` при первом входе сверяет email
    с белым списком `allowed_staff` и только тогда заводит профиль с ролью.
- **Где:** `supabase/migrations/0001_auth_roles.sql`, `0002_catalog.sql`.

### service_role vs anon ключ
- **anon** (`NEXT_PUBLIC_SUPABASE_ANON_KEY`) — для браузера, ограничен RLS.
- **service_role** (`SUPABASE_SERVICE_ROLE_KEY`) — полный доступ, **обходит RLS**, только на сервере.
- **Где:** `src/lib/supabase/admin.ts` (помечен `server-only`).

### Supabase Auth + Google OAuth
- **Что:** вход через Google или email+пароль, сессия в cookies.
- **Где:** `/admin/login`, `app/auth/callback`, роль — из таблицы `profiles`.

### Supabase Storage
- **Что:** файловое хранилище с публичными бакетами и CDN.
- **Где:** бакет `media` (папки `products/`, `banners/`), обёртка — `src/lib/storage.ts`.
- Чтение публичное, запись — только service-role с сервера.

### sharp
- **Что:** быстрая нативная библиотека обработки изображений.
- **Зачем:** привести любое загруженное фото к WebP и разумному размеру.
- **Где:** `src/lib/imageUpload.ts` (авто-поворот по EXIF, ресайз, WebP q82).
- **Нюанс:** на Vercel требует явного включения нативных бинарей в
  `next.config.mjs` — иначе роут падает с `ERR_DLOPEN_FAILED`.

### Canvas API (браузер)
- **Что:** сжатие фото ещё до отправки на сервер.
- **Зачем:** обойти лимит тела запроса Vercel (~4.5 МБ) — фото с телефона тяжелее.
- **Где:** `src/lib/clientImage.ts`.

### Telegram Bot API
- **Что:** отправка сообщений ботом в чат через HTTP-запрос.
- **Где:** `src/lib/telegram.ts` + роуты заказов и отзывов.

## 6. Инструменты и инфраструктура

- **Node.js / npm** — среда выполнения и менеджер пакетов (`package.json`).
- **Git / GitHub** — версионирование, репозиторий `hesychast` (SSH-доступ).
- **Vercel** — хостинг: авто-деплой при `git push`, серверные функции, переменные
  окружения; аналитика `@vercel/analytics` и `@vercel/speed-insights`.
- **ESLint** (`next lint`) и **tsc** (`tsc --noEmit`) — проверка кода и типов.
- **pg** (dev-зависимость) — применение SQL-миграций скриптом
  `scripts/apply_migrations.mjs` через session pooler.

## 7. Что в бэклоге (см. STATUS.md)
- **SEO-слой**: отдельные URL товаров и категорий, `generateMetadata`,
  `robots.ts`, `sitemap.ts`, JSON-LD — приоритет №1.
- **`next/image`** вместо `<img>` — вес страницы и LCP.
- **ISR/кэш** вместо `force-dynamic` на главной.
- **Upstash Redis** — распределённый rate-limit вместо in-memory.
