# Новый магазин на базе Sushi Syndicate — анализ и поэтапный план

> Документ создан: 2026-07-23, обновлён под уточнение. Основа — существующий проект `sushi-shop/` (Next.js 15 + Supabase + Vercel + Telegram).
> Цель: функциональная копия суши-шопа для **обычного магазина одного продавца**, но с товарами **проще** (без ингредиентов/КБЖУ) и слегка изменённым внешним видом.

---

## 0. Итоговая концепция (что строим)

**Бренд: ІСИХАСТ** — православная крамница. Продавец — православный священник. Ассортимент: **православный мерч** + **продукты с его пасеки** (мёд и т.п.). Витрина — украинский язык. Визуальный тон — сдержанный, «церковный»: для H1/названия бренда используется церковный/классический шрифт (сейчас интерим `Old Standard TT`, задел под настоящий церковнославянский устав/вязь — Fedorovsk/Ponomar Unicode, self-host).

Магазин **одного продавца** (не маркетплейс). Владелец сам добавляет товары через админку, покупатель кладёт в корзину и оформляет заказ, заказ уходит **в Telegram** владельцу. Архитектурно это **тот же суши-шоп** — меняется только:

- **товар упрощён** до: название, цена, опционально описание/граммовка, фото, категория (без ингредиентов, КБЖУ, состава, расчёта порций);
- **другой внешний вид** (рескин: цвета/типографика/лого/hero);
- **универсальные товары** вместо суши (тексты, категории, оферта).

Всё остальное — корзина, чекаут, заказы в Telegram, админка, вход, загрузка фото — переиспользуется **как есть**.

### Что значит «товары закидывают люди сами»
Владелец магазина (админ) сам заводит товары через `/admin/products` — CRUD товаров с загрузкой фото уже реализован в суши-шопе. Отдельные аккаунты продавцов/регистрация **не нужны** (это был бы маркетплейс — мы это отменили).

### Принятые решения

| Вопрос | Решение |
|---|---|
| Кол-во продавцов | **Один** (магазин одного владельца), как суши-шоп |
| Модель сделки | Корзина + заказ, данные в Telegram (как сейчас) |
| Оплата | Без онлайн-оплаты, оплата при получении (как сейчас) |
| Товар | Название + цена + описание? + граммовка? + фото + категория |

### Зафиксировано
- **Ниша:** православный мерч + продукты пасеки. **Язык:** украинский. **Бренд/папка:** `iesihast/`.
- **Промокоды — удаляем.** **Баннеры — оставляем** (в них грузятся акционные фото). **Акции — оставляем.**
- Переиспользуем **полностью**, лишнее заказчик частично уберёт сам; сейчас в объёме — только вырезать **ингредиенты и всё связанное** (КБЖУ, состав, граммовка-расчёт) + удалить промокоды.

### Открытые вопросы (решить по ходу)
1. Настоящий церковнославянский шрифт для H1 (файл устава/вязи) — заказчик пришлёт, тогда self-host вместо интерим Old Standard TT.
2. Реальные категории под ассортимент (мерч / мёд / …).

## 1. Стратегия: копировать и упростить

Переиспользование ≈ **85–90%**. Путь — **скопировать `sushi-shop/` → `marketplace/`**, поднять новый git/Supabase/Vercel/бота, затем **вырезать лишнее из товара** и **сделать рескин**. Основная работа — не в логике (она готова), а в упрощении модели товара и во внешнем виде.

### Берём как есть (без изменений)
- Каркас Next.js 15 App Router + TS + CSS Modules, конфиги.
- **Вход** (Supabase Auth / Google OAuth), `middleware`-гард `/admin`, роли, белый список сотрудников `allowed_staff`.
- **Корзина** (`CartContext` + localStorage, `CartDrawer`).
- **Чекаут + заказ** `/api/order` (валидация, пересчёт цен из БД, rate-limit, запись в `orders`/`order_items`, Telegram) — практически без изменений.
- **Загрузка фото** `/api/upload` → клиентское сжатие (`clientImage.ts`) → `sharp` → WebP → **Supabase Storage**, бакет `media` (папки `products/`, `banners/`).
- **Telegram** `src/lib/telegram.ts` (один чат владельца).
- **Админка**: `AdminShell`, `Pagination`, `AdminSearch`, `Modal`, CRUD категорий и товаров, просмотр заказов, смена статусов.
- **Отзывы + модерация** (`reviews`, `/admin/reviews`, `/api/review`) — оставляем как есть.
- Rate-limit, `slugify`, `settings`, страницы приватности/оферты.

### Упрощаем (главная работа)
- **Товар** — вырезаем ингредиенты, КБЖУ, граммовку-расчёт, состав, бейджи; форма/карточка/модалка становятся простыми.

### Выкидываем
- Таблицы/код: `ingredients`, `product_ingredients`, `set_items`, `price_history`, `src/features/nutrition.ts`, bulk-цены по ингредиенту.
- Страницы админки: `/admin/ingredients`, `/admin/price-history`, `/admin/subcategories` (подкатегории — опционально оставить), `BulkPriceTool`, `catalogPdf`.
- Поля товара: `composition`, `full_desc` (оставляем одно `description`), `pieces`, `badge`, `is_hit`, связи с ингредиентами, `portion`.
- **Промокоды** (`promo_codes`, `/admin/promo-codes`, поле промокода в чекауте, `promo_code_id`/`discount` в `orders`).
- **Оставляем:** акции (`promos`), баннеры (`banners`, `HeroPromoSlider`, загрузка акционных фото в `/admin/promos`).

## 2. Модель данных (упрощённая)

Основное отличие от суши-шопа — только в таблице `products`. Остальное почти без изменений.

```
products              -- УПРОЩЁН
  id                uuid pk
  category_id       uuid references categories(id) on delete set null
  name              text not null
  slug              text unique
  description       text                 -- опционально (было short_desc/full_desc/composition)
  price             numeric(10,2) not null
  weight            text                 -- опционально «290 г», «0.5 кг»
  image_path        text
  is_available      boolean default true
  sort_order        int default 0
  created_at        timestamptz
  -- УБРАНО: short_desc, full_desc, composition, pieces, badge, is_hit,
  --         product_ingredients, promos, portion

categories            -- как есть (name, slug, sort_order, show_in_nav, is_active)
orders / order_items  -- как есть (можно убрать promo_code_id/discount, если без промокодов)
profiles / allowed_staff / settings / reviews  -- как есть
```

RLS — как в суши-шопе: публичное чтение каталога, запись — `is_staff()`, удаление — `is_admin()`.

Схему делаем **одной новой init-миграцией** (новый Supabase-проект), не тащим 12 миграций суши-шопа.

## 3. Поэтапный план (фазы)

### Фаза 0 — Bootstrap (~1–2 ч)
- [ ] Скопировать `sushi-shop/` → `marketplace/`, удалить `.next`, `node_modules`, `.git`.
- [ ] `git init`, новый GitHub-репозиторий.
- [ ] Новый проект Supabase, новый бакет R2, **новый Telegram-бот** (BotFather), новый чат/группа для заказов.
- [ ] Новый `.env.local` (свои ключи Supabase/R2/бот), обновить `.env.example`.
- [ ] Переименовать проект в `package.json`, метаданные (title/favicon — временно).
- [ ] `npm run dev` поднимается (пока со старой логикой суши).

### Фаза 1 — Упростить товар + вырезать лишнее (~4–6 ч, ядро работы)
- [ ] Новая init-миграция: упрощённый `products`, `categories`, `orders`/`order_items`, `profiles`, `allowed_staff`, `settings`, `reviews`, RLS.
- [ ] Удалить из кода: `nutrition.ts`, ингредиенты, `set_items`, `price-history`, bulk-цены, (промо/акции/баннеры по решению).
- [ ] Удалить страницы админки: `/admin/ingredients`, `/admin/price-history`, (`/admin/promos`, `/admin/promo-codes`), `catalogPdf`.
- [ ] Упростить тип `Product` (`src/lib/types.ts`) → name, price, description?, weight?, photo, category.
- [ ] Упростить `MenuCard`, `ProductModal` (убрать КБЖУ, состав, бейджи ХІТ/НОВЕ, «шт»).
- [ ] Упростить форму товара `/admin/products` (имя, цена, описание, граммовка, фото, категория).
- [ ] Прогнать сборку, убрать битые импорты. Магазин работает на простых товарах.

### Фаза 2 — Наполнение и настройка (~2–3 ч)
- [ ] Завести реальные категории под нишу магазина (`/admin/categories`).
- [ ] Добавить несколько товаров через админку (проверка загрузки фото в R2).
- [ ] Настроить белый список сотрудников (`allowed_staff`) — доступ владельца в админку.
- [ ] Проверить заказ end-to-end: корзина → чекаут → Telegram → запись в `/admin/orders`.

### Фаза 3 — Ребрендинг / внешний вид (~4–6 ч)
- [ ] Новые цвета/типографика/лого (токены в CSS), Hero под новую нишу.
- [ ] Тексты витрины, «О нас», футер, оферта/приватность под новую сущность.
- [ ] Адаптив-проверка (мобильное меню, карточки, модалка).

### Фаза 4 — Деплой и прод-проверка (~2–3 ч)
- [ ] Vercel-деплой, автодеплой из GitHub, домен.
- [ ] Прод-чек-лист: заказ → Telegram; вход владельца в админку; добавление/редактирование товара; отзыв → модерация.

**Итого грубо: ~13–20 часов** (большая часть готова, работа — в упрощении товара и во внешнем виде).

## 4. На что обратить внимание
- **Telegram-бот** не пишет пользователю, пока тот не нажал `/start` в чате/группе заказов — один раз настроить.
- **Не сломать защиту цен** в `/api/order` (сервер пересчитывает цены из БД) и rate-limit при упрощении.
- **`force-dynamic`** на главной из суши-шопа — если товаров станет много, заменить на ISR/пагинацию (бэклог).
- Если промокоды/акции решим **оставить** — не удалять соответствующие таблицы/код (фаза 1).
