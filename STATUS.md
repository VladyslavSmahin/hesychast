# ІСИХАСТ — статус и роадмап

Живой рабочий журнал проекта. Архитектура — в `ARCHITECTURE.md`, исходный план и
история решений — в `PLAN.md`, учёт времени — в `WORKLOG.md`.

**Что это:** православная крамница одного продавца (священник) — православный мерч
и продукты с собственной пасеки. Витрина на украинском, заказы уходят в Telegram
владельцу, товары заводятся через собственную админку. Онлайн-оплаты нет —
оплата при получении, доставку менеджер считает вручную.

**Репозиторий:** `git@github.com:VladyslavSmahin/hesychast.git` (ветка `main`).
**Прод:** ещё не развёрнут (Vercel-проект локально не слинкован, `.vercel/` отсутствует).

## ✅ Сделано

### Каркас и витрина
- Next.js 15 (App Router) + React 19 + TypeScript, шрифты через `next/font`
  (Cormorant Garamond, Jost, Old Standard TT как интерим церковного шрифта).
- Главная `/` — Hero с баннер-слайдером, каталог с фильтрами и сортировкой,
  блок «Хіти», отзывы, «Про нас», карта, футер. Мобильный UX (категорийный бар,
  бургер-меню, компактная модалка товара).
- Корзина: `CartContext` + `localStorage`, `CartDrawer` с чекаутом (имя, телефон
  с валидацией формата, адрес, комментарий, согласие на обработку ПД).
- Инфо-страницы: `/about`, `/oferta`, `/privacy` (шаблоны — нужна вычитка юристом
  и реальные реквизиты продавца).

### Данные и заказы
- Весь каталог читается из Supabase на сервере (`publicData.server.ts` →
  `PublicDataProvider`); данные кэшируются под тегом `PUBLIC_TAG`, админка
  сбрасывает кэш после каждой правки.
- Демо-фолбек: пока в БД нет товаров, витрина показывает демо-каталог из
  `src/data/demo.ts` — исчезает сам, как только появятся реальные товары.
- Акции: активная акция в пределах дат и ниже каталожной цены даёт эффективную
  цену на витрине (цена + зачёркнутая старая) — и на карточке, и в корзине.
- Заказ `/api/order`: цены и названия берутся **исключительно из БД** (подмена
  цены на клиенте игнорируется), лимиты на количество позиций и длину полей,
  rate-limit 6/мин по IP, запись в `orders` + `order_items`, уведомление в Telegram.
  При падении и БД, и Telegram — честная `502`, корзина не очищается.
- Отзывы `/api/review`: приём с сайта (rate-limit 4/мин), модерация в админке,
  на витрину идут только `approved`.

### Админка (`/admin`)
- Вход через Google OAuth (Supabase Auth) + вход по паролю для сотрудников;
  пароль сотруднику задаёт главный админ через `/api/admin/staff/password`.
- Доступ проверяется **на сервере** в `middleware` по роли из `profiles`
  (заполняется триггером только для email из `allowed_staff`); чужой Google-аккаунт
  получает экран отказа (`?denied=1`).
- Разделы: товары (CRUD + загрузка фото), категории, акции и баннеры Hero
  (drag&drop порядок), заказы (список + доска с фильтром по дате, смена статуса),
  отзывы (модерация), сотрудники, глоссарий текстов сайта.

### Хранилище изображений (2026-08-07)
- **Supabase Storage**, публичный бакет `media` (лимит 8 МБ, только `image/*`),
  папки `products/` и `banners/`.
- Путь загрузки: клиентское сжатие (`clientImage.ts`, обход лимита тела запроса
  Vercel ~4.5 МБ) → `/api/upload` → `sharp` → WebP q82 → Storage → URL в БД.
- Запись только service-role с сервера; проверено, что публичным anon-ключом
  залить файл нельзя.
- Cloudflare R2 убран полностью (был унаследован от исходного проекта):
  снят `@aws-sdk/client-s3`, удалены все переменные `R2_*`. Отдельных ключей
  под хранилище больше не нужно — работает на ключах Supabase.

### Схема БД
Миграции `supabase/migrations/0001_auth_roles.sql` и `0002_catalog.sql` применены
к проду напрямую через session pooler (`scripts/apply_migrations.mjs`).
10 таблиц, RLS на всех. Упрощённый товар: без ингредиентов, КБЖУ, состава,
подкатегорий, промокодов и истории цен. Миграции суши-шопа лежат в
`supabase/migrations/_archive_sushi/` как справка — **не применять**.

> которые можно дать со стороны кода; дальше решают тексты, реальные отзывы и время.

## 🔑 Переменные окружения

Локально в `.env.local` (в `.gitignore`), шаблон — `.env.example`:

| Переменная | Зачем |
|---|---|
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | уведомления о заказах и отзывах |
| `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` | публичный доступ к БД (под RLS) |
| `SUPABASE_SERVICE_ROLE_KEY` | сервер: заказы, отзывы, загрузка в Storage |
| `SUPABASE_DB_URL_SP` | session pooler, для разовых скриптов миграций |
| `NEXT_PUBLIC_SITE_URL` | **пока не задана** — настоящий домен магазина. До неё сайт закрыт от индексации, canonical и sitemap указывают на временный адрес |

В Vercel Production нужны первые три группы (`SUPABASE_DB_URL_SP` — только локально).
Отдельных ключей под хранилище картинок больше нет.

⚠️ **Как купите домен:** прописать `NEXT_PUBLIC_SITE_URL=https://<домен>` в Vercel →
индексация, canonical и sitemap переключатся сами. Только после этого подавать
сайт в Google Search Console.

## ⚠️ Не забыть

- **Не запускать `supabase db push`** — схему применяли напрямую SQL-скриптом,
  таблица миграций рассинхронизирована. Изменения БД делать через
  `scripts/apply_migrations.mjs` или SQL Editor.
- **Прямое подключение `db.<ref>.supabase.co` не резолвится локально** (IPv6) —
  использовать session pooler (`aws-1-eu-central-1.pooler.supabase.com`).
- **`sharp` на Vercel**: нативная libvips грузится через `dlopen`, трейсер Next её
  не видит → роуты с `sharp` падают с `ERR_DLOPEN_FAILED`. Решено в
  `next.config.mjs` (`outputFileTracingIncludes` для `@img/**` + `serverExternalPackages`
  + ленивый `import("sharp")`). **При добавлении нового роута с `sharp` — дописать его туда.**
- **Telegram-бот** не напишет в чат, пока там один раз не нажали `/start`.
- Демо-фолбек в `publicData.server.ts` маскирует пустой каталог — если на витрине
  видны «чужие» товары, значит в БД их нет либо запрос упал.
- **Витрина кэшируется.** Правка данных напрямую в БД (SQL Editor, скрипт) на
  сайте появится только через минуту — админка сбрасывает кэш, а прямая правка нет.
- **Публичные данные читаются клиентом без cookies** (`src/lib/supabase/anon.ts`).
  Обычный серверный клиент читает cookies, и тогда Next считает страницу
  персональной: кэш не работает, каждый заход идёт в БД. Если добавляете новый
  публичный запрос — берите анонимный клиент.
- В `features/admin/db.ts` остались мёртвые функции для `ingredients` и
  `subcategories` — таких таблиц в схеме нет, в UI они не используются.
